MEMORY / PROCESS MONITOR

画面を見ながら、手動で整理する

まずはプリセットなしで、しばらく使わないアプリを1つ選ぶところから。
「何を選ぶか」「どこを押すか」「結果をどう読むか」を順に説明します。

01初めての整理：この5操作でOK

ZIPを展開し、MemCleanM.exeを起動します。画面のアプリタブを開いてください。

  1. 「用途」は「手動（プリセットなし）」のままで始める

    初回はプリセットの作成不要。上部のAVAILABLE / 利用可能と状態メッセージを確認します。「メモリ余裕あり」なら、必要なときまでそのままで大丈夫です。

  2. しばらく使わないアプリを探す

    検索欄に名前を入力するか、一覧から探します。たとえばゲーム中に使わない音楽プレーヤーなど、自分で使っていないとわかるアプリを選びます。名前がわからないものは、選ばずに残せます。

  3. 行の左端のチェックボックスを押す

    行の背景をクリックするだけでは整理対象に入りません。左端をチェックし、画面左下が選択 1件以上になったことを確認します。同じアプリが複数のプロセスを持つ場合、件数は複数になります。

  4. 選択対象を確認して「選択プロセスを整理」を押す

    検索外の選択も含めて整理します。左下の選択件数を押すと、選択した対象全体を見直せます。確認後、右下の選択プロセスを整理を押してください。

  5. 下部の結果を見る

    整理が終わると、下部に結果 実行 … / スキップ …が出ます。ここを押すと対象別の詳細を表示します。画面を開いたまま30秒待つと、もう一度計測して履歴を更新します。

整理すると、何が起きる？ 選んだプロセスのRAM常駐量を縮小します。アプリ終了やデータの破棄は行いません。次に使うときに必要なメモリが再び読み込まれ、少し遅くなる場合があります。

04整理後の結果を読む

整理が終わると、一覧の下に結果の横長ボタンが出ます。そのボタンを押すと、同じ画面で対象別の詳細を開けます。

表示意味
実行 / スキップ実際に整理した件数 / 整理しなかった件数。「CPUを使用中」などの理由は詳細で確認します。
常駐減少各対象のRAM常駐量の「実行前 − 直後」の合計。+500 MiBなら常駐量が500 MiB減っています。
利用可能差PC全体の利用可能メモリの「直後 − 実行前」。プラスなら増加、マイナスなら減少。他のアプリの動作も含みます。
実行前 / 直後 / 30秒後同じプロセスのRAM常駐量を、それぞれの時点で測定した値です。
欠測終了・再起動・取得不可などで、同じプロセスの30秒後の値を測れなかった件数。0 MiBとして計算しません。

例：620 → 120 → 260 MiB

直後に常駐量が500 MiB減り、30秒後には140 MiB戻った例です。アプリが必要なデータを再び使うと、常駐量が増えることがあります。整理後もずっと小さくなるとは限りません。

30秒後の計測を見たいとき

整理が終わったら、アプリを最小化せずに開いておきます。操作やタブの切替はできます。30秒後に同じ履歴が更新されます。

次の整理を開始・最小化・アプリ終了すると、追跡計測を中止し、その理由を履歴に残します。整理後すぐに閉じることもできます。

以前の結果は「実行履歴」へ

実行履歴タブで、左上の日時一覧から記録を選びます。直後と30秒後の値、実行・スキップの理由を見直せます。最大100件を保存します。

05いつもの組み合わせをプリセットにする

プリセットは「整理候補のアプリ」と「その用途で守りたいアプリ」を保存する仕組みです。「ゲーム前」「画像生成前」などの名前を自分で付けられます。

  1. 「アプリ」タブで、いつも整理したいものをチェック

    例：ゲーム中に使わないBrowserとMusicPlayer。ここでは整理ボタンを押さず、候補を選ぶだけです。

  2. 「プリセット」タブで名前を入力して「新規」

    プリセットを開き、名前に「ゲーム前」を入力して新規を押します。その時に選択していたEXEを候補として保存します。

  3. 必要なら、その用途で守るアプリを登録

    保護設定タブで現在の用途で保護を選び、対象を追加します。毎回守るアプリは共通保護へ登録します。

  4. 次回は「用途」を選び、対象を確認して整理

    「アプリ」タブ上部の用途を切り替えると、現在起動中の登録候補を選び直します。その後、左下の件数を確認して手動で整理します。

ボタン使う場面
再適用同じ用途で、後から起動したアプリも取り込みたいとき。現在の選択を起動中の登録候補へ置き換えます。

用途の切替・再適用は、選択を置き換えます。 先に手動で選んでいたものは選び直されます。保護設定は候補より優先。再起動後は前回の用途の保護を復元し、選択は0件から始まります。

同じ名前でもEXEの場所が違えば別の登録です。別EXEの補助プロセスをまとめて扱いたいときは、それぞれを同じプリセットへ追加してください。

06使うアプリを保護する

今使うアプリの常駐量を維持したい場合は、保護へ登録します。たとえば画像編集・生成をするなら、編集アプリや生成アプリを保護してから、他のアプリを整理します。

起動しているアプリから登録

  1. 「アプリ」タブで対象を探します。見つからなければすべてへ切り替えます。
  2. その行の設定を押すか、行を右クリックします。
  3. 常に保護またはこの用途で保護を選びます。

起動していないアプリも登録

  1. 保護設定タブを開きます。
  2. 左上で共通か現在の用途を選びます。
  3. EXEを追加を押し、守りたいアプリの実行ファイルを選びます。
保護の種類いつ適用？登録する例
共通：常に保護用途を変えても、手動モードでも適用。常に使う編集アプリや作業ツール。
現在の用途で保護そのプリセットを選んでいる間に適用。「ゲーム前」のゲーム本体、「画像生成前」の生成アプリ。
固定・作業中の保護Windows等の固定条件や、操作中・直前に使ったアプリの条件で適用。Windowsの処理、重要なプロセス、別ユーザー、別セッション、MemCleanM自身など。

用途別の保護を登録するには、先にプリセットを作成・選択します。解除したい場合は、保護設定の対象行で解除を押します。共通・用途別の両方へ登録している場合、もう一方の保護が残る間は引き続き保護されます。

保護はEXEのフルパスごとです。別EXEの補助プロセスも守る必要があるなら、そのEXEも追加してください。整理の直前にも同じプロセスか、保護対象か、CPUを使用中かを確認します。

08困ったとき

「選択プロセスを整理」が押せない

左端のチェックを入れ、左下の選択件数を確認してください。行の背景を選んだだけでは対象に入りません。保護中のものは選べません。画面に保護設定・プリセット設定の破損メッセージがある場合も整理を停止します。

アプリが見つからない / 一覧が空になる

検索欄を空にし、絞り込みを「すべて」に変えてください。初期表示の「整理可能」では保護中のアプリが隠れます。起動直後は数秒待ちます。権限などで情報を取得できないプロセスは、「取得不可」の件数に入り、操作対象として表示できません。

「低負荷候補」に何も出ない / 計測中のまま

起動直後は約18秒の計測が必要です。アプリを最小化せずに待ってください。RAM常駐量64 MiB未満のものや、CPUが継続して低負荷ではないものは候補に入りません。候補を待たず、使っていないとわかるアプリを手動で選ぶこともできます。

候補なのに「CPUを使用中」でスキップされた

実行直前に状態を再確認します。その時点でCPUが1コア換算10%を超えるなど、保護条件に該当するとスキップします。作業が落ち着いたあとに、必要な対象だけ選び直してください。一覧のCPU表示は全コア換算なので、この判定とは換算が異なります。

整理したのに、空きメモリが増えない / 減った

各アプリの常駐量には共有ページがあり、減った常駐量がそのまま空き容量にはなりません。他のアプリが同時にメモリを使うこともあります。「常駐減少」と「利用可能差」を別々に確認してください。

30秒後の値が「—」 / 中止 / 欠測になった

スキップした対象は追跡計測しません。次の整理・最小化・アプリ終了でも追跡を中止します。実行した対象が終了・再起動したり、取得できなくなったりした場合は欠測です。「—」や欠測はメモリ0を意味しません。

保護を解除したのに、まだ選べない

共通と現在の用途の両方に登録していないか確認してください。Windows等の固定条件や作業中アプリの保護も優先されます。プリセット候補に登録していても、保護条件に該当すれば整理対象から外れます。

「この用途で保護」「選択を追加」が使えない

「手動（プリセットなし）」では用途別の登録先がありません。「プリセット」タブで名前を入力して「新規」を押すか、作成済みの用途を選んでください。「選択を追加」は、先にアプリ一覧で追加したいものをチェックします。

ゲームや画像生成のVRAM不足にも効く？

整理するのはRAM常駐量です。GPUのVRAM不足、メモリリーク、アプリのメモリ確保量やコミット上限の問題を解消する機能ではありません。

設定はどこ？ 更新すると消える？

%LOCALAPPDATA%\MemCleanMに保存します。共通保護はsettings.json、プリセットはprofiles.json、表示設定はui-state.json、履歴はhistoryフォルダです。アプリを終了して新しいZIPを展開すれば、同じPCでは設定を引き継げます。

保護・プリセット設定が壊れていると表示された

誤った保護状態で整理しないよう、整理を停止しています。アプリを終了し、表示された保存先のファイルをバックアップしてから修復してください。ファイルを削除して初期化すると登録した保護も消えるので、内容を確認して対応してください。表示設定だけの破損では初期表示へ戻ります。

最小化・終了すると何が止まる？

最小化すると定期監視を停止し、30秒後の追跡計測も中止します。終了するとアプリは終了し、トレイ常駐しません。整理中に閉じた場合は中止要求を出し、実行済みの結果を保存してから終了します。30秒待機のために終了が遅れることはありません。
